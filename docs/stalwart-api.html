Stalwart API study

Written 2026-10-07 for the server at version 0.16.25. This page is a coding map. It does not contain passwords, keys, or mail.

Stalwart does not offer one API key that both reads mail and administers the server. It offers two JMAP APIs. They share the same JSON shape, then split.

The shape every call uses

A call is one HTTP POST. Several methods can ride in the same body. The server answers with methodResponses in the same order.

{
  "using": ["urn:ietf:params:jmap:core"],
  "methodCalls": [
    ["Method/name", { }, "call-1"]
  ]
}

There is no large REST catalogue of mail routes. The official reference for the management objects is stalw.art/docs/ref/. The helper HTTP routes are documented at stalw.art/docs/development/api/.

Door 1: mail

This is the door a mailbox tool should use.

ItemValue on this server
SessionGET https://webmail.cryptocomputing.ca/jmap/session
CallsPOST the apiUrl from that session. Today that is https://webmail.cryptocomputing.ca/jmap/
LoginAuthorization: Basic with the account password or an app password. An OAuth access token also works as Authorization: Bearer. An API key does not open this door.
SpecRFC 8620, plus the mail, submission, and calendar JMAP specs

The session returns the account id and the methods the account may call. The methods a mail client needs first are Mailbox/query, Email/query, Email/get, Email/set, EmailSubmission/set, and Identity/get. Upload a large attachment with a POST to the session's uploadUrl, then refer to the returned blob id.

On this host, nginx forwards only /jmap on webmail.cryptocomputing.ca to Stalwart. The rest of that host is the webmail application.

IMAP on port 1143 and SMTP submission on port 1587 accept the same account password or app password. They also advertise OAUTHBEARER and XOAUTH2. Most mail programs cannot use those token mechanisms, which is why an app password exists.

Door 2: administration

This is the door a server tool should use.

ItemValue on this server
CallsPOST https://emailadmin.cryptocomputing.ca/api
SchemaGET https://emailadmin.cryptocomputing.ca/api/schema
Who am IGET /api/account returns permissions, edition, and locale
LoginBasic auth for a person. For a program, create an API key and send Authorization: Bearer with that key.
CapabilityAdd urn:stalwart:jmap to the using array

Nginx on emailadmin.cryptocomputing.ca forwards the whole site to Stalwart. That is the right base URL for this door.

Method names look like x:Account/query, x:Domain/get, and x:DkimSignature/set. Settings that exist once per server use the id singleton. For example, x:Imap/get is called with "ids": ["singleton"]. Real lists, such as accounts, domains, and keys, use query, then get, then set.

set accepts create, update, and destroy. The secret for a new API key or app password comes back once, inside created. After that the server stores only a hash.

The schema endpoint is the spec a program should trust. It is JSON Schema for every object, field, and enum on this exact server version. The official stalwart-cli downloads that schema and builds its commands from it. A client can do the same and avoid hard-coding the object list. The human catalogue is the reference linked above.

A call the identity is not allowed to make returns a JMAP error. It does not return an empty list. GET /api/account shows the permission list for the signed-in identity. An API key can inherit the account's rights, drop some of them, or carry only an explicit list.

Objects to learn first

  • Account, Domain, DkimSignature
  • ApiKey and AppPassword
  • NetworkListener and QueuedMessage
  • Singletons: Imap, Jmap, Authentication, SystemSettings

Enterprise-only objects are marked in the catalogue. Live tracing and live metrics are in that group. This server currently logs that its enterprise license does not renew, so those two streams should be treated as unavailable.

Credentials, in one paragraph

An app password replaces the mailbox password on Door 1 and on IMAP or SMTP. Create it while signed in as the mailbox owner, under Account, Credentials, App Passwords. An administrator can see and revoke one, and cannot create one for someone else. An API key opens Door 2 only. It cannot read or send mail. Create it under Account, Credentials, API Keys. Both secrets are shown once.

What to build

A mailbox tool should use Door 1 only. Start with Basic auth against /jmap/session, store apiUrl and the account id, and ignore /api.

A server tool should use Door 2 only. Point it at https://emailadmin.cryptocomputing.ca, send an API key as a bearer token, and fetch /api/schema before the first real call. The JSON envelope above is the entire client.
